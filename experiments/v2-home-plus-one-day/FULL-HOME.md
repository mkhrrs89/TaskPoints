# Full Home acceptance for V2-owned Task actions

The full synthetic Home page keeps showing the acknowledged V2 Task date through
reload, Notes navigation, lifecycle refresh, ordinary Save, Task journal
compaction, verified-secondary maintenance, and Chromium restart. Unrelated
data continues through the existing V1 paths. The [Inbox preservation fix](INBOX-STARTUP-LOSS.md)
adds a notification generated by the real Inbox to the same acceptance fixture.

## Title edits

The existing Home Edit and Save controls trim the title and keep the prior
title for blank input. Save uses the Task revision that was visible when
Edit opened, so a refresh can keep the draft without letting it overwrite
a competing edit.

V2 commits the title, update timestamp, and receipt together. The editor
closes after verified readback. Retrying the same unconfirmed save reuses
its receipt ID and title. Reopening verifies that a title receipt changed
only the title and timestamp. Ordinary Home saves still use the V1 backing
state, and the existing detached rollback checkpoint carries the verified
title and date into a fresh V1 profile.

## Importance and Tags

The selected synthetic Task uses the same Home editor for Importance and
Tags. The dropdown keeps its four existing choices. The tag input splits
on commas, trims whitespace, drops empty entries, and keeps order, case,
and duplicates. Clearing the input removes existing tags. Tags with
quotes and angle brackets display as literal text in both editors.

One Save commits the changed fields and any title change in a single V2
receipt. Startup verifies that receipt against the previous Task and
checks that every unrelated field is unchanged. A retry after an
unconfirmed save must use the same fields. Title-only receipts keep their
existing format. Direct Due Date editing and Repeat (including its
custom count and unit) remain V1 fields and are read-only on the
selected synthetic Task.

The browser tests exercise the Home card, Work tag styling, and the
phone-width Critical Tasks indicator. They verify legacy save and
compaction, maintenance, Chromium restart, and a fresh V1 rollback that
keeps the latest fields, a pending unrelated Task journal, Inbox and
other app records, unknown fields, and image bytes.

## Points and earned rewards

The same Home Points input keeps V1's numeric conversion. Blank input
saves zero, and the editor accepts negative, decimal, and exponent
values. V2 admits only finite numbers. A single receipt can commit
Points with any changes to Title, Importance, and Tags.

The legacy Done action copies the Task's points into a completion.
Scoring totals use that stored completion value. A Points edit changes
only the Task row and receipt, leaving completed rewards, Game and
Gold records, and backup bytes intact. The history test uses an actual
recurring completion and a completed one-off Task. It checks that the
past day's total stays at 8 points and that a later completion earns
12.75 points after restart and verified rollback into a fresh V1
profile.

Home refuses legacy Done for the selected synthetic Task while V2
owns it. The legacy path would otherwise award from the stale V1
Task. The existing Done flow is available in the fresh V1 profile
after rollback. Completing a Task while V2 owns it needs a separate
implementation.

## Done ownership checkpoint

Home Done normally captures the Task's current Points in a completion,
checks for a completion on the same local day, and updates the Task and
completion together in the legacy journal. It closes one-off Tasks.
Recurring Tasks advance from their current due date using the existing
recurrence rules and reset their postponement count. The action also
shows the Points toast, updates the Today list and Critical Tasks
indicator, and animates the card. Home's live score and matchup
calculations read completions from the legacy state.

Commit `31bc2d20` preserves the browser witness for the original bug.
After Home changed Points from 5 to 12.75, a newly opened Today page
awarded 5 through its own `saveStateSnapshot` path.

Home and Today now call the same check in the shipped scoring core before
either completion handler can mutate state, award Points, save a
snapshot, journal a completion, or update the Today list. This check
reserves only synthetic Task `t1` on a loopback origin with the ownership
marker. It reads the marker at the point of use, treats malformed bytes
as a hold, and retains a hold for the lifetime of a document that saw
the marker. The old Home owner check remains as a fallback.

The browser tests exercise both controls with an already-open Today tab
and a fresh Today tab. The app loads the shared scoring core in both,
including the root Today URL with the bare core. Neither tab needs the
injected Home owner or synthetic runtime flag to refuse. Repeated
concurrent attempts preserve the stored Tasks, completions, scores,
journals, backups, and Today list. The test also checks a Chromium restart
with malformed marker bytes, marker loss in a loaded document, an
unrelated Task completion, and a fresh detached V1 rollback that awards
12.75 once through the normal Today control. That last award is V1.

The shared check covers the current Home and Today code. An older build
without the check can still write. A new document after loss of the
marker cannot distinguish marker loss from a fresh V1 profile. Keep the
old-client and controlled handoff requirements open.

V2 Done remains paused. Home's `computeTodayPoints` and the canonical
`syncYouMatchups` pipeline still consume V1 completion totals. Before a
V2 award can be enabled, the score display and persisted matchup
calculations must use the same verified completion set and defer writes
when verification fails. Showing only the correct Home total could leave
a persisted Game result calculated from stale rewards. An eventual V2
transaction must commit the Task, completion, and receipt together and
enforce one award per Task and local day inside that transaction.

Today-list state lives in a separate localStorage record. The completion
receipt can supply the Task ID, local day, and initiating control for
reconciliation after commit or restart. The Today checkbox should be
derived from the verified completion. Any persisted list cleanup should
use the latest day map and remove only the affected Task ID and its
order entry, leaving other order entries, notes, and habits intact.
Removing the same entry again is harmless. An unreadable day map should
be preserved. This reconciliation has its own verification and cannot
be part of the IndexedDB commit.

The next prerequisite is a verified completion read path for Home,
Today, and persisted Game/matchup scoring, exercised with seeded
synthetic completion records before enabling either Done writer.

## How the integration works

- The loopback harness explicitly selects a single synthetic Task and checks the
  fixture marker against V2 metadata. The Home card and Critical Tasks display use
  a separate view verified against the durable V2 receipt chain. The card waits for
  that read at startup and stays withheld if V2 cannot be verified. Lifecycle
  refresh rereads V2 even when the V1 revision did not change.
- Home keeps the V1 backing state and storage cache on their legacy values. The
  V2 display is not passed to ordinary snapshot, journal, maintenance, or backup
  writers. Both the original localStorage and native IndexedDB boot paths still run.
- V2 checks the canonical owned Task, its linked completions, its pending Task
  journal evidence, the legacy generation, and the existing recovery holds. The
  read and transaction checks refuse genuine conflicts and unreadable evidence.
  Unrelated Task compaction and verified-secondary diagnostics can change without
  disabling V2 edits. The component experiment retains its original full-source check.
- Rollback freezes V2 at the verified revision, reads the current legacy snapshot,
  and inserts only the verified owned Task into a detached candidate. A fresh
  synthetic V1 profile opens at the latest V2 date and keeps the latest unrelated
  Task edit. Original/current legacy strings and receipts remain archived. The
  source images and journals are left in place. This checkpoint exercises Task
  compatibility. PR #1004 retains the separate full storage-transfer format.

## Evidence and limits

The loopback tests run checked-in Home HTML and its real controls, Notes
navigation and the core script order derived from `_worker.js`. The service
provides static assets and the bundle without Cloudflare HTML rewriting. Test
profiles use only synthetic data and block external browser requests.

The acceptance cases assert the actual Task card date after each path. They track
first paint on reload to catch a temporary stale date. The tests also cover quota,
before and after commit interruption, stale V2 and competing V1 edits, malformed
journals, missing receipts, and the detached rollback checkpoint. The preservation
checks compare the unrelated Task, Habit, Flex, Game, Gold, Projects, Notes,
unknown Task fields and raw keys, quarantine evidence, and exact image bytes.
Habit comparisons omit three named derived display counters that ordinary Home
adds on save. The Inbox comparisons use an actual generated notification, and the dedicated
cold-start test requires that the ordinary startup snapshot save preserve it.

The experiment covers +1 Day and edits to Title, Importance, Tags,
and Points on one synthetic Task. The
installed iPhone handoff, real-data transfer, and old-client transition
requirements remain unresolved. Ordinary V1 storage and UI paths retain
their existing behavior with the experiment disabled.
